# Security model and limits

The Compose network isolates the API from public host ports, while the dashboard and demo app bind to loopback only. Admin and worker Bearer tokens are independent and required for privileged endpoints. Admin authorization is coarse-grained (one administrator). Runtime secrets live only in an ignored `.env`; do not submit it in issues, PRs, or logs. No shell command received from a model is executed.

The worker is the only service mounting `/var/run/docker.sock` in the disposable demo Compose profile. The separate [continuous monitor](continuous-monitor.md) profile removes the socket from the worker and uses a GET-only proxy on an internal network; it disables restart and production log capture. The proxy still permits GET access to other container metadata, so it is not per-container data isolation. The demo profile's raw socket is **not** a least-privilege Docker API boundary: a compromised worker bypasses its code allowlist and has effective host control, so run that profile only on a disposable daemon/VM. The continuous-monitor proxy blocks writes but a compromised worker can still read unrelated Docker metadata. Dashboard token lives in sessionStorage, so an XSS would expose it; use localhost with trusted code. No TLS is provided. The demo app's `/break` and `/reset` routes are intentionally unauthenticated on loopback.

Restart is disabled by default in both API and worker. Approval alone cannot execute restart while `HEALOPS_AUTO_RESTART=false`. An approved restart is claimed once with an attempt cap; retries, circuit breaker recovery, authenticated deployment, PR creation, rollback, CI sandbox patching, code diff review, and Kubernetes driver are **not implemented**. The `Deployment` model reserves schema for later work; it is not a rollback implementation. A failure is marked failed and not retried. Unknown actions are rejected. No arbitrary Docker command is dispatched.

Log capture is limited to 8 KiB but not guaranteed to redact every secret; keep credentials out of application logs and use only the demo on a test daemon. Optional LLM input consists of recent logs and status. Do not set a model endpoint that you don't trust with these logs. LLM output is parsed into a strict shape, but is informational only; deterministic policy creates restart plans. LLM outages fall back to rules.

Risk reduction before production: mount a constrained socket proxy with enforceable per-endpoint authorization, isolate worker on a separate daemon/host, use TLS and a real identity provider, add secrets scrubbing, encrypted data storage, durable job leases and replay protection, signed deployment artifacts, explicit health/HTTP checks, rollback, and external threat review.
