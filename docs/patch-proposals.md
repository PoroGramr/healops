# Experimental Codex worktree/PR adapter

`backend/app/patches.py` is opt-in and **not connected to the production incident loop**. It creates a temporary Git worktree, checks an exact file allowlist, runs Codex once with a timeout, rejects unregistered paths and symlinks, tests changed code in a separate networkless read-only Docker container using a preloaded image digest and fixed argv, and optionally pushes a branch and opens a GitHub PR. It never merges a PR or deploys a container. Local unit tests cover path rejection, worktree isolation, local-remote push and mocked PR creation. **No actual GitHub PR has been created.**

The host's native Codex `workspace-write` mode failed: bubblewrap could not use Linux user namespaces and patch writing failed despite CLI exit 0. The adapter now runs Codex in a **separate ephemeral Docker container**, non-root, without the Docker socket, with a read-only filesystem, dropped capabilities, resource caps and only the temporary worktree and Git metadata mounted. Codex runs without an *inner* sandbox because the container is its sandbox. The user's existing Codex OAuth file is mounted read-only for model access. Its contents remain readable to a compromised process **inside that network-enabled job**; this residual credential-exfiltration risk was explicitly accepted for this host. Use a dedicated, limited credential if available. Never pass production `.env`, host home or Docker socket to the patch job.

The containerized adapter was exercised with **real Codex inference** on a disposable Git fixture: it changed `BUG = True` to `BUG = False` only within an allowlisted file, passed a test in a second Docker container with `--network none`, and returned a validated diff. `publish=False` ensured no GitHub write. The runner image is built from `patch-runner/Dockerfile` and pinned by its local SHA256 image ID in the policy; the separate test image must also be preinstalled and pinned by digest.

Do not enable automatic PR merging or production deployment yet. PW3 production does not capture logs; healthcheck-only evidence cannot justify an autonomous source fix. The existing PW3 Actions deploy workflow builds every `main` push but has no automated rollback. Required before promotion: sanitized actionable evidence, baseline/post-patch tests, CI review, artifact provenance, health-gated deployment and proven rollback. An LLM-generated command is never forwarded to a shell outside the isolated Codex job.
