# Experimental Codex worktree adapter (disabled)

`backend/app/patches.py` provides an opt-in proposal function. It validates a registered repository and exact file allowlist, creates a temporary Git worktree, invokes authenticated Codex CLI in `workspace-write` mode once with a timeout, rejects any changed path outside the allowlist/symlinks, tests the candidate in a preinstalled digest-pinned Docker image with no network/socket and read-only source, and optionally pushes a branch and opens a GitHub PR. It never merges a PR or deploys a container. Unit tests exercise path rejection, isolation, local Git push and mocked PR creation; **no actual remote PR has been created**.

The real Codex smoke test on this host did **not** generate a patch. The CLI reports that its Linux bubblewrap sandbox requires user namespaces, and its patch write failed even though it exited with code 0. The adapter failed closed because the worktree had no changes. Do not bypass Codex's sandbox on the production host. This path is not wired to incidents and must remain disabled until tested in an isolated job/VM with minimal credentials and working sandbox. A model-generated fix based only on a healthcheck and no sanitized logs is not grounded enough to release automatically.

Before enabling any PR-to-production path: provide actionable sanitized evidence, sandboxed Codex execution, baseline and post-patch tests, exact changed-file review, working CI, deployment transaction and rollback. The existing PW3 GitHub Actions workflow deploys every `main` push and currently has no automatic rollback; **do not automatically merge HealOps-generated PRs**.
